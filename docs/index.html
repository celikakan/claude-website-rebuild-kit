Website-Rebuild mit Claude Code: Der komplette Leitfaden

Ihre Webseite, neu gebaut: alle Inhalte bleiben, das Design wird modern. Von der Einrichtung über 37 Skills bis zum Livegang auf WordPress, mit einem Installations-Befehl und Ihrer Freigabe an jedem wichtigen Punkt.

Manuelle Installation

einmalig, 4 Schritte

Die Grundausstattung, falls noch nicht vorhanden: VS Code als Arbeitsumgebung und Claude Code als KI-Werkzeug darin. Einmal einrichten, dann nie wieder.

  • 1. VS Code installieren Kostenloser Editor von Microsoft, herunterladen und installieren wie jedes Programm. code.visualstudio.com
  • 2. Node.js installieren Wird von mehreren Werkzeugen gebraucht, die LTS-Version wählen. nodejs.org
  • 3. Claude Code installieren Im Terminal ausführen: npm install -g @anthropic-ai/claude-code, danach einmal claude tippen und mit Ihrem Claude-Konto anmelden. claude.com/claude-code
  • 4. Claude-Code-Extension in VS Code In VS Code links auf das Extensions-Symbol klicken, "Claude Code" (von Anthropic) suchen und installieren. Damit läuft Claude direkt im Editor. VS Code Marketplace

Ein Projekt starten

pro Projekt, 4 Schritte

So beginnt jede Arbeit: jedes Kundenprojekt bekommt seinen eigenen Ordner, und Claude Code wird IN diesem Ordner gestartet. Dauert eine Minute.

  • 1. VS Code öffnen und im Menü Datei > Ordner öffnen wählen.
  • 2. Neuen Projektordner anlegen im Dialog auf Neuer Ordner klicken, sprechend benennen, z.B. website-rebuild-firmenname, dann öffnen.
  • 3. Claude Code Extension öffnen auf das Claude-Symbol in der Seitenleiste klicken, das Claude-Panel öffnet sich. Hier arbeiten Sie ab jetzt.
  • 4. Loslegen Claude arbeitet automatisch in diesem Projektordner und liest dessen CLAUDE.md (nächste Sektion). Erste Anweisung eintippen, fertig.
So ist Ihr Arbeitsplatz aufgebaut
┌─────────────────────────────────────────────────┐ │ VS Code │ │ ┌─────────────┐ ┌────────────────────────────┐ │ │ │ EXPLORER │ │ CLAUDE CODE (Extension) │ │ │ │ │ │ │ │ │ │ Dateiliste │ │ Hier arbeiten Sie: │ │ │ │ des Projekts│ │ Anweisungen in normaler │ │ │ │ │ │ Sprache oder /befehle. │ │ │ │ CLAUDE.md │ │ │ │ │ │ index.html │ │ Claude antwortet, baut │ │ │ │ ... │ │ und fragt vor Aenderungen │ │ │ │ │ │ um Ihre Freigabe. │ │ │ └─────────────┘ └────────────────────────────┘ │ │ ┌─────────────────────────────────────────────┐ │ │ │ TERMINAL: nur fuer manche Installationen │ │ │ │ (z.B. den Install-Befehl des Skill-Kits) │ │ │ └─────────────────────────────────────────────┘ │ └─────────────────────────────────────────────────┘

Die Systematik in 3 Sätzen: 1. Sie geben Ihre Anweisungen im Claude-Code-Panel ein, in normaler Sprache oder per /befehl. 2. Claude erstellt und ändert daraufhin Dateien im Projektordner, links im Explorer sehen Sie jede neue Datei erscheinen, und vor Änderungen fragt Claude um Ihre Freigabe. 3. Das Ergebnis prüfen Sie im Browser: sagen Sie Claude einfach "öffne die Seite im Browser", oder nutzen Sie /webapp-testing für den automatischen Test. Sie programmieren nie selbst, Sie geben Anweisungen, geben frei und prüfen Ergebnisse.

Und das Terminal? Manche Installationen müssen im Terminal erfolgen, deshalb ist dieser Bereich nur dann wichtig. Öffnen: Menü Terminal > Neues Terminal.

CLAUDE.md erstellen

das Projektgedächtnis

Die CLAUDE.md ist das Gedächtnis Ihres Projekts: eine Textdatei im Projektordner, die Claude Code bei jedem Start automatisch liest. Ohne sie startet Claude jedes Mal bei null und muss das Projekt neu erkunden. Mit ihr weiß es sofort, welche Technik im Einsatz ist, welche Befehle gelten und welche Regeln einzuhalten sind, wie ein Einarbeitungs-Dokument für einen neuen Mitarbeiter.

Grundregel: Jedes Projekt hat seine EIGENE CLAUDE.md, im jeweiligen Projektordner. Dazu gibt es genau EINE persönliche CLAUDE.md, die für Sie in allen Projekten gilt. So sieht das auf Ihrem Rechner aus:

So liegen die Dateien auf Ihrem Computer
Ihr Computer │ ├── ~/.claude/CLAUDE.md ← 1x persoenlich: Ihre Vorlieben, │ gilt automatisch in ALLEN Projekten │ └── Projekte/ ├── website-kunde-a/ │ ├── CLAUDE.md ← gehoert NUR zu Projekt A │ └── ... (Projektdateien) │ └── website-kunde-b/ ├── CLAUDE.md ← gehoert NUR zu Projekt B └── ... (Projektdateien)

Öffnen Sie Claude Code im Ordner von Projekt A, liest es automatisch die persönliche Datei PLUS die von Projekt A. Projekt B bekommt davon nichts mit. Deshalb: neues Kundenprojekt = neuer Ordner = neue, eigene CLAUDE.md.

So entsteht Ihre CLAUDE.md, je nach Ausgangslage:

Fall A, Sie starten bei null (leerer Projektordner): /init bringt hier nichts, denn es analysiert vorhandene Dateien, und es gibt noch keine. Übernehmen Sie stattdessen das Beispiel unten: sagen Sie Claude einfach "Lege eine CLAUDE.md mit folgendem Inhalt an" und fügen das Beispiel ein (Firmenname anpassen). Fertig.

Fall B, das Projekt hat schon Dateien (z.B. nach Phase 1, wenn Inhalte und Design-Werte gesichert sind, oder bei einem bestehenden Projekt): einmal /init tippen, Claude analysiert alles Vorhandene und erzeugt die Datei daraus.

Wichtig: einmal pro Projekt, nicht pro Sitzung. Die Datei bleibt im Projektordner liegen und Claude Code liest sie danach bei jedem Start automatisch. Sie müssen nie wieder etwas eingeben. Gepflegt wird sie nebenbei: nach einer Korrektur einfach "speichere das ins Gedächtnis" sagen (Tipp 1 unten).

Beispiel: CLAUDE.md für den Website-Rebuild
# Projekt: Website-Rebuild firmenname.at ## Technik - Statisches HTML/CSS/JS, Ziel-System: WordPress (via novamira) - Design-Werte stehen in design-tokens.css und sind verbindlich ## Befehle - Lokale Vorschau: index.html im Browser oeffnen - Seite testen: /webapp-testing ## Regeln - Design-Tokens und Vorlagen-Struktur NIE eigenmaechtig aendern - Alle Inhalte kommen vom Original, nichts erfinden - Kein "fertig" ohne Beweis (Screenshot oder Test)

Fürs Team: die Projekt-CLAUDE.md wird über Git mit dem Team geteilt, so arbeiten alle nach denselben Regeln. In die persönliche Datei unter ~/.claude/CLAUDE.md gehören nur Ihre eigenen Vorlieben (z.B. Sprache, Kommentar-Stil).

Drei Profi-Tipps aus dem offiziellen Anthropic-Video:

1. Wenn Sie Claude korrigieren mussten, sagen Sie danach "speichere das ins Gedächtnis", dann steht die Regel ab sofort in der CLAUDE.md und gilt dauerhaft.
2. Eigene Dokumente einbinden mit dem @-Zeichen: @docs/anleitung.md.
3. Kompakt halten: lieber klein starten und nur ergänzen, was Sie wirklich korrigieren mussten. Eine kurze, präzise CLAUDE.md wirkt besser als eine lange.

Quelle: Anthropic, "The CLAUDE.md file" (YouTube, 3 Min.)

Installation des Skill-Kits (One-Click Installation)

1 Befehl

Öffnen Sie das Programm Terminal. Mac: Cmd+Leertaste drücken, „Terminal" eintippen, Enter. Windows: Startmenü öffnen, „Git Bash" eintippen, Enter (kommt automatisch mit Git, Download: git-scm.com). Dann diese Zeile einfügen und Enter drücken:

Im Terminal einfügen
curl -fsSL https://raw.githubusercontent.com/celikakan/claude-website-rebuild-kit/main/install.sh | bash

Installiert automatisch alle 37 Skills aus diesem Dokument plus die Werkzeuge firecrawl, novamira, gh (GitHub CLI), ffmpeg und yt-dlp, und zeigt am Ende eine Erfolgsliste. Danach Claude Code einmal neu starten. Kit auf GitHub: github.com/celikakan/claude-website-rebuild-kit

Später erweitern: neue Skills werden im Kit in der Datei skills-manifest.txt ergänzt (eine Zeile pro Skill). Denselben Befehl erneut ausführen, die Installation aktualisiert sich selbst.

Was sind Skills?

Grundwissen

Ein Skill ist ein Wissenspaket für Claude Code: eine Anleitung, wie eine bestimmte Aufgabe professionell erledigt wird. Technisch ist es ein kleiner Ordner mit einer Anleitungsdatei, der auf Ihrem Rechner unter ~/.claude/skills/ liegt. Man kann sich einen Skill wie eine Checkliste eines Spezialisten vorstellen: der SEO-Skill denkt wie ein SEO-Berater, der Design-Skill wie ein Art Director.

Wie werden Skills angewendet? Auf zwei Wegen:

1. Automatisch: Claude erkennt an Ihrer Aufgabe, welcher Skill passt, und wendet ihn selbstständig an. Sagen Sie "mach einen Screenshot von meiner Webseite", nutzt Claude von allein den Playwright-Skill. Sie müssen nichts auswendig wissen.

2. Gezielt per Befehl: Sie tippen einen Schrägstrich und den Skill-Namen, z.B. /website-rebuild. Damit starten Sie den Skill direkt und zuverlässig. Das ist der empfohlene Weg für die großen Arbeitsschritte in diesem Dokument.

Beispiel 1 · gezielt
/grill-me

Sie tippen: "/grill-me ich will meine Webseite neu bauen lassen".
Was passiert: Claude stellt Ihnen der Reihe nach Fragen (Ziel, Zielgruppe, Design-Wünsche, was bleiben muss) und hört erst auf, wenn alle offenen Punkte geklärt sind. Ergebnis: ein sauberer Plan statt Missverständnisse.

Beispiel 2 · automatisch
superpowers

Sie tippen: nichts, das Plugin läuft immer mit.
Was passiert: Sagen Sie "baue die Startseite", zwingt superpowers Claude zur Disziplin: erst Fragen klären, dann bauen, und "fertig" gibt es nur mit Beweis (z.B. einem erfolgreichen Test). Schützt vor schnellen, schlampigen Ergebnissen.

Beispiel 3 · automatisch
playwright-skill

Sie tippen: "Mach einen Screenshot von meiner-seite.at in Handy-Größe".
Was passiert: Claude öffnet die Seite in einem echten Browser, stellt die Bildschirmgröße ein und speichert den Screenshot. Genauso kann es durch Vorbild-Seiten klicken und deren Aufbau erfassen.

Beispiel 4 · gezielt
/website-rebuild

Sie tippen: "/website-rebuild".
Was passiert: Der Haupt-Skill fragt Ihre Webseiten-Adresse und die Design-Vorlage ab und arbeitet dann 9 Schritte ab: Inhalte sichern, Design nachbauen, Seiten zusammensetzen. An 3 Punkten werden Sie um Freigabe gebeten.

Beispiel 5 · gezielt
/brand-board

Sie tippen: "/brand-board" und geben Ihre Webseite plus Logo/Unterlagen an.
Was passiert: Claude extrahiert Farben, Schriften und Tonalität und baut daraus ein professionelles Brand Board, die verbindliche Design-Grundlage für den Rebuild.

Beispiel 6 · gezielt
/seo-aeo-audit

Sie tippen: "/seo-aeo-audit meine-seite.at".
Was passiert: Claude prüft die Seite in 6 Schritten für Google UND für KI-Suchen (ChatGPT, Perplexity) und liefert einen deutschen Maßnahmenplan mit Prioritäten.

Design System - Brand Book erstellen

2 Prompt-Vorlagen

Zwei Prompts für Phase 2: der erste lässt Claude das bestehende Designsystem einer Webseite exakt dokumentieren, der zweite macht daraus ein druckfertiges Brand Book als PDF. Einfach kopieren, die Beispiel-Adresse durch die echte ersetzen und in Claude Code einfügen.

Prompt 1: Designsystem analysieren
# Rolle Du bist ein erfahrener Design-System-Analyst und Art Director. Du dokumentierst die Designsprache bestehender Websites exakt und wertfrei, ohne eigene Gestaltungsideen einzubringen. # Aufgabe Analysiere das komplette visuelle Designsystem der folgenden Website und dokumentiere es als verbindliches Design-System: https://www.example.com # Kontext Die Website selbst ist die einzige Quelle der Wahrheit. Grundlage ist die tatsächlich im Browser gerenderte Seite, nicht Vermutungen und nicht Branchenstandards. Das Ergebnis dient als Design-Grundlage fuer einen Website-Rebuild: neue Seiten muessen damit exakt zum Original passen. # Anleitung Gehe in dieser Reihenfolge vor: 1. Oeffne die Website im Browser. Erfasse die Startseite und 2-3 typische Unterseiten. 2. Extrahiere praezise, mit exakten Werten: a) Farben: Primaer-, Sekundaer-, Akzent-, Flaechen- und Textfarben b) Typografie: Schriftfamilien, Schriftgroessen, Schriftschnitte, Zeilenhoehen c) Abstaende und Raster: Spacing-Skala, Grid-System, Containerbreiten d) Formen: Eckenradien und Schatten e) Komponenten: Buttons, Karten, Formulare, Navigation, jeweils alle Zustaende (normal, Hover, aktiv, deaktiviert) f) Icons, Bildstil und Hintergruende g) Visuelle Hierarchie: wie Groesse, Farbe und Abstand die Aufmerksamkeit lenken h) Responsive-Verhalten: Handy, Tablet, Desktop i) Bewegung: Animationen, Uebergaenge, Scroll-Effekte 3. Pruefe jede Angabe am gerenderten Original nach (Computed Styles, Screenshots), bevor du sie dokumentierst. # Regeln - Gestalte die Marke NICHT neu und interpretiere nichts um. - Dokumentiere ausschliesslich, was existiert. Keine Verbesserungsvorschlaege. - Jede Angabe mit exaktem Wert. Keine Umschreibungen wie "dunkelblau". # Ausgabe Erstelle genau drei Dateien: 1. DESIGN.md, das Designsystem im Ueberblick 2. design-guidelines.md, verbindliche Gestaltungsregeln mit allen Werten 3. design-components.md, Komponenten-Katalog mit exakten Massen und Zustaenden # Qualitaetskriterium Ein anderer KI-Agent muss allein mit diesen drei Dateien neue Seiten bauen koennen, die visuell nicht von der bestehenden Website zu unterscheiden sind.
Prompt 2: Brand Design als PDF
# Rolle Du bist ein Brand-Designer und Art Director, spezialisiert auf Brand Books und Markendokumentation in Druckqualitaet. # Aufgabe Erstelle aus dem dokumentierten Designsystem ein professionelles Brand Book als druckfertiges PDF im A4-Format. # Kontext Grundlage sind die drei Dateien aus der Designsystem-Analyse (DESIGN.md, design-guidelines.md, design-components.md) sowie die Logo-Dateien und weitere Markenunterlagen, falls vorhanden. Das Brand Book dient Kunde, Agentur und KI-Agenten als verbindliches Nachschlagewerk der Marke. # Anleitung 1. Baue das Brand Book mit dieser Kapitelstruktur, je Kapitel eine Seite oder Doppelseite: a) Deckblatt mit Logo und Markenname b) Markenuebersicht: Positionierung und Tonalitaet in 3-4 Saetzen c) Logo: Varianten, Schutzraum, Mindestgroessen, verbotene Anwendungen d) Farben: Palette mit exakten Werten (HEX, RGB, CMYK) und Einsatzregeln e) Typografie: Schriftfamilien, Schnitte, Groessenhierarchie, Beispiele f) Bildsprache: Stil, Motive, erlaubte und verbotene Beispiele g) Komponenten: Buttons, Karten, Formulare mit exakten Massen h) Anwendungsbeispiele: Website, Briefpapier, Social Media 2. Setze das Brand Book zuerst als HTML im A4-Format um (Skill brand-book-paper) und pruefe das Layout Seite fuer Seite. 3. Exportiere als PDF und kontrolliere: Seitenumbrueche, Lesbarkeit, Farbtreue, keine abgeschnittenen Elemente. # Regeln - Nutze ausschliesslich die dokumentierten Markenwerte. Erfinde nichts dazu. - Das Brand Book selbst muss im Design der Marke gestaltet sein: ihre Farben, ihre Schriften, ihre Bildsprache. - Druckqualitaet: A4, saubere Raender, konsistente Kopf- und Fusszeilen. # Ausgabe Erstelle genau zwei Dateien: 1. brand-book.html, das A4-Layout, druckfertig 2. brand-book.pdf, das finale Dokument # Qualitaetskriterium Das PDF muss so professionell sein, dass eine Design-Agentur es als bezahltes Deliverable an ihren Kunden uebergeben koennte.

Passende Skills dazu: design-system, brand-book-html und brand-book-paper (Phase 2) machen aus der Analyse die fertigen Dokumente.
